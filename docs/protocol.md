# Protocol reference

Current public release: the finite command definitions in `packages/protocol/src/commands.ts` and negotiated capabilities are authoritative. Historical sections below describe earlier protocol milestones and retain the same wire framing. Current-file support supersedes the initial unsupported read source; see [architecture](architecture.md) and [compatibility](compatibility.md).

# Web Control protocol v1

`@dsh-web-control/protocol` is independent of DSH, Node APIs, relay persistence and browser UI. It exports the canonical types, strict parsers and bounded transport primitives. Wire envelopes always contain `v: 1`. Unknown messages, operations, fields, malformed JSON, non-finite numbers and unsafe integers fail explicitly. `ProtocolError` carries `code`, `message` and `retryable`; oversized JSON is terminal `LIMIT_EXCEEDED`, including the byte bound in its message. It must not trigger repeated resynchronization of the same oversized snapshot.

## Identity, authentication and fencing

Protocol-generated instance, runtime, control, correlation, lease and transfer IDs are canonical lowercase UUID strings. DSH session/workspace/receipt/delivery identifiers and stop tokens remain nonempty opaque Host identifiers. A prompt's canonical UUID business `requestId` is separate from its call correlation `id` and survives reconciliation of an uncertain response.

Every business message carries the complete `{instanceId, authEpoch, runtimeId, controlId}` Fence. `authEpoch` is a positive safe integer, starting at 1 for a fresh identity; zero is invalid in persisted identities, Fences, Host hello and relay acknowledgment. The authenticated socket binds instance/runtime/auth; the binary control ID is checked against its current Fence. Replacing a Fence, disconnecting, cancelling a transfer or disposing the plugin must dispose every affected transfer and clear its queues. Parsing is structural validation; consumers must also validate the Fence against the authenticated socket and scope before executing anything.

Host authentication credentials belong only in the WSS Upgrade `Authorization` header. Browser credentials belong only in the Secure/HttpOnly/SameSite cookie. Localhost authentication tokens never enter protocol JSON. All fixed schemas reject credential fields; arbitrary JSON payloads recursively reject `localhostToken`, `localToken`, `__proto__`, `prototype` and `constructor`. Arbitrary JSON contains finite JSON values only, plain objects and arrays, no accessors, nonenumerable properties, functions, inherited prototypes or symbols. Maximum JSON value nesting is 64. Free text values must be projected by their producer without credentials; structural validation cannot identify a secret embedded in prose.

## Handshake sequence

Handshake messages have separate `HandshakeMessage` types and `parseHandshake`; they cannot pass `parseController` as browser commands.

The public canonical origin is HTTPS. Task-owned loopback HTTP/WS tests model the internal listener behind TLS termination; the relay does not terminate TLS itself. Fixed HTTP routes are `POST /v1/devices/register`, `POST /v1/instances/:id/login`, `POST /v1/instances/:id/logout`, `POST /v1/instances/:id/control-status`, `GET /v1/host` (Host upgrade), `GET /v1/instances/:id/control` (browser upgrade), and `/health/live`, `/health/ready`. Enrollment JSON is `{enrollmentSecret,instanceId,deviceSecret,linkVerifier,authEpoch}`; login JSON is `{secret}`. Logout authenticates the instance cookie and expires it. Missing cookies are `AUTH_REQUIRED`. Browser writes/upgrades require an exact canonical `Origin`; device enrollment and Host upgrades are a separate authentication role.

The complete v1 sequence for Host and browser consumers is:

1. Host upgrades `/v1/host` with `Authorization: Bearer <deviceSecret>` and `X-DSH-Instance: <instanceId>`. The relay verifies the credential before upgrading. Cookies cannot authenticate this route. Within five seconds Host sends `host.hello` with instanceId, runtimeId, versions, capabilities, authEpoch, linkVerifier, enabled, and optional **complete** `limits`. Omitted Host limits mean the configured relay limits.
2. Relay negotiates version 1, claims exclusive socket ownership, and only then calls authorization synchronization. A duplicate `HOST_ID_IN_USE`, including a higher-epoch duplicate, cannot mutate the active owner's persisted authorization. Lower epochs or divergent equal epochs fail with `AUTH_EPOCH_CONFLICT`. Failed synchronization removes only the newly claimed socket.
3. Relay sends existing `relay.ack {version:1,authEpoch,linkVerifier,enabled}`, followed by `relay.config {limits,heartbeatMs,leaseTtlMs}` to Host. Effective limits are the per-field minimum of relay and advertised Host limits. Host must apply these limits and configured timing before handling attach/business traffic. No local credential appears in JSON.
4. Browser upgrades `/v1/instances/:id/control` with the instance HttpOnly cookie and exact Origin, then sends `browser.hello {versions:[1],resume?:{id,secret}}`. The optional resume values are its previous lease id and resumeSecret. All authentication occurs before lease admission. Browser cannot send Host messages, relay configuration, detach or faults.
5. Relay sends `relay.config` with **the same effective limits and timing** advertised to Host, then `browser.lease {id,resumeSecret,fence,expiresAt}`. Browser retains the lease credentials in page/session state and acknowledges receipt with `browser.lease-ack {id}`. The initial browser hello and lease acknowledgment share a five-second deadline. Business traffic is forbidden during these stages.
6. Only after that acknowledgment relay sends Host `attach {id,leaseId,fence}`. Host verifies current authorization and installs its HostFence before returning `host.attached {id,fence}`. The matching request id and every Fence field must agree. The attach deadline is ten seconds, also bounded by the lease's business inactivity deadline. A mismatched Fence rejects the attempt; stale ACKs for previous request ids are ignored.
7. Relay rechecks current authorization, Host route, and lease generation after ACK, then sends `ready {fence}`. Browser may now send business messages. A queued ready/business frame also rechecks ownership immediately before sending. Acquiring a lease alone never means ready.

All listed envelopes have `v:1` and central strict schemas. Resume secrets are canonical 32-byte base64url values, stored only as hashes inside LeaseTable. A dropped initial lease delivery, missing lease acknowledgment, failed attach, or close before ready releases the exact attempted controlId. Once ready, a confirmed browser disconnect retains the lease for its **existing** inactivity deadline; it never extends that deadline. Resume requires the matching lease id/secret, a disconnected lease, and a newly authenticated socket; it changes controlId. Resume cannot steal an online lease. After expiry or relay restart the same authorized page may acquire a new lease, so a provided old resume tuple does not require an old lease to exist.

An established Host may send `host.auth {authEpoch,linkVerifier,enabled}`. Relay synchronizes it only on that authenticated owning socket, acknowledges with `relay.ack`, revokes the previous control and pending attach on an epoch change, and releases any disconnected old lease. Browser cookie sessions deleted by rotation require fresh link authorization. A Host never sends detach: relay sends `detach {fence}` when that generation loses ownership. Host must invalidate only a matching Fence, abort its observers/transfers, and leave already accepted Agent work running. No disconnect, lease expiry, timeout, backpressure or revocation generates a business `cancel`. Delayed old-generation Host events/chunks are discarded.

Handshake/admission failures use `fault {error:{code,message,retryable}}` where delivery remains possible. Diagnostic text is sanitized to the code. Oversized JSON is terminal `LIMIT_EXCEEDED` (WebSocket close 1009); clients must not retry the same oversized snapshot. Other semantic faults close with 1008 and a bounded code reason. If a queue/socket cannot carry a fault, the close reason conveys `RESYNC_REQUIRED`; a transport failure can instead produce an abnormal close without a reason. `HOST_OFFLINE` and `RESYNC_REQUIRED` permit reconnect/resynchronization, not replay of uncertain business actions. `RESULT_UNCERTAIN` requires business-specific reconciliation. Authentication faults require reauthorization; `REMOTE_BUSY` preserves legacy/resume-only occupancy. Optional `browser.hello.takeover: true` permits an authenticated, strictly parsed and negotiated deliberate fresh-page/manual claim to replace ownership atomically. Retired pages receive terminal `REMOTE_REPLACED`; automatic connection recovery must omit takeover. Host attach/detach wire is unchanged. Ping/pong only detects transport death. Valid current browser business messages, including `heartbeat`, renew the lease; Host messages and stale messages never renew it.

Relay limits unauthenticated HTTP connections and pending Host handshakes to 64, HTTP authorization bodies to 4096 bytes, and aggregate authorization HTTP attempts to 60 per fixed reset interval of 60 seconds. This is a single-process deployment guard, not a per-user rate guarantee. HTTP header/body and initial socket handshake deadlines are five seconds. Host initial `maxPayload` is configured before allocation using relay limits; browser allocation uses the already negotiated effective limits. All later frames also pass their specific effective JSON/chunk bounds. Compression is disabled. No Origin credentials are reflected via CORS.

The single per-instance send queue charges both directions, queue metadata, and the sum of actual Host/browser `bufferedAmount`. Control frames overtake data; upload.end/download.end share data ordering so end never overtakes its chunks. Only one frame is submitted at a time, with at most one 64 KiB payload chunk per event-loop turn. Cancelled/stale queued frames are skipped before dispatch. Call/watch/upload and outstanding download admission, credits, sequential chunk counts, exact bytes, call timeouts, transfer idle deadlines, and lease sweeps are enforced by the relay. Transfer progress is valid bytes, never credit alone. Slow transport fails with `RESYNC_REQUIRED`. Limits affect observers and transfers; they do not cancel accepted Agent work.

The packaged relay exports `startRelay` from `@dsh-web-control/relay/server`. Its build bundles the protocol and includes `dist/migrations/001.sql` beside the compiled database module's relative migration path. Deployment CLI/service configuration, Host adapters and browser UI are separate consumers.

## Business messages

Controller operations are exactly `session.list`, `session.create`, `session.prompt`, `session.page`, `session.stop`, `interaction.answer`, `file.read`, `file.changes`, `file.diff`. Watches are exactly workspaces, sessions, session and interactions. Other controller envelopes are call, watch, cancel, upload.open, upload.end, download.credit and heartbeat. Host envelopes are result, event, end, upload.credit and download.end. Generic Host `end` terminates a watch; download.end terminates a byte transfer.

Every field is required unless marked optional by the exported types. All sequence, index, offset, byte and count fields are nonnegative safe integers; maxMessages is positive. Binary index is uint32. File read length is 0 through 1 MiB, additionally limited by fileBytes; offset plus length must stay safe. Opaque identifiers, names, paths, media types and timezone strings contain 1 through 4096 UTF-16 code units. Text content may be empty; prompt content has 1 through 1024 parts. The complete JSON frame bound still applies. Protocol version lists contain 1 through 32 positive uint16 entries; capabilities have at most 128 strings.

`Fault.code` permits future explicit codes; exported ERROR_CODES includes AUTH_REVOKED, HOST_OFFLINE, HOST_ID_IN_USE, REMOTE_BUSY, REMOTE_REPLACED, STALE_CONTROL, STALE_ACTION, OUT_OF_SCOPE, WRITER_HELD, BACKPRESSURE, LIMIT_EXCEEDED, RESULT_UNCERTAIN, PROTOCOL_UNSUPPORTED, RESYNC_REQUIRED, INVALID_MESSAGE, TRANSFER_CLOSED and TRANSFER_TIMEOUT. Retrying a business action requires its business-specific safety policy; a transport retry does not make stop or answer replay-safe.

### Cancellation, completion and timeout races

Within one Fence the relay tracks typed operation identities through active, retired and completed states. Explicit cancel or a local timeout retires the affected identity and disposes its observers/transfer accounting. Only known, kind-appropriate late frames are discarded: call/upload results, watch events/end, upload credits and download chunks/end. Wrong-kind and genuinely unknown identities still fail. Late upload bytes/end and download credits for already retired transfers are ignored without renewing business activity. A late cancelled/timed-out file.read result can introduce a distinct download identity; that identity is also retired so its later end/chunks cannot invalidate unrelated operations.

Retirement waits for the Host's ordered terminal: result for call/upload, end for watch, download.end for download. A terminal marks completed without cancelling its normal queued delivery. Queue callbacks hold identity objects, not a lookup that could bind an older callback to a reused id; cancelled queued frames are suppressed. A cancel overtaking a not-yet-dispatched opener suppresses both opener and cancel and completes that local identity. If an opening file.read result has already reached relay, cancelling its call also retires its associated download locally.

Retention is derived from effective advertised limits: deadline `max(1000, callTimeoutMs, transferIdleMs)` milliseconds; total active/recent identity capacity `max(16, min(4096, 4 * (calls + streams + uploads)))`. Recent IDs cannot be reused. Completed records expire after that deadline, or the oldest completed record can be evicted to admit a fresh ID, only after all its queued control frames have been skipped or their WebSocket send callbacks have settled. An ordered terminal proves prior Host frames drained; callbacks additionally retain the original identity token. Undrained retired records are never evicted or reused: their deadline or a capacity exhausted by non-evictable records causes explicit RESYNC_REQUIRED and a new Fence. Clients should generate fresh UUIDs for all operations; they must not infer safe reuse from a locally displayed timeout.

Call timeout emits a normal result with `ok:false` / RESULT_UNCERTAIN for that call, preserving uncertainty about already accepted mutations. Active upload byte timeout emits a result with TRANSFER_TIMEOUT; waiting for its durable receipt uses RESULT_UNCERTAIN. Download idle timeout emits download.end with TRANSFER_TIMEOUT. These retire only the operation, leaving unrelated watches/calls usable while bounded drain proceeds. They do not synthesize business cancel. For a same-Fence explicit `cancel` whose opener was dispatched, Host consumers must send the kind-appropriate terminal once that observer/transfer drains: call/upload → `result`, watch → `end`, download → `download.end`. An already queued normal terminal satisfies this obligation. Otherwise a cancelled read/query/upload may return a result error (for example TRANSFER_CLOSED); a cancelled watch may send plain end; a cancelled download may send download.end with TRANSFER_CLOSED and its observed chunk count (error ends do not require exact declared bytes). A possibly accepted mutation must preserve its actual receipt/result or RESULT_UNCERTAIN; an observer cancellation must never claim that accepted Agent work was cancelled. The relay discards these retired-operation terminals, using them only as proof of drain. Omitting the terminal leaves the identity undrained and eventually requires resync, so normal same-Fence session switches must complete this drain protocol.

Generation detach/disconnect is different: Host invalidates only the matching Fence and disposes its observers/transfers; no per-operation terminal is required after that generation is gone. Late old-generation terminals are harmlessly discarded by the relay. Already accepted Agent work continues in both cases.

## Upload and download framing

Uploads: Controller sends `upload.open` with transfer id, Fence, sessionId, name, mediaType and exact bytes. Host grants `upload.credit {id,fence,chunks}`. Controller sends credited binary chunks and finishes with `upload.end {id,fence,chunks}`. Host verifies all counts and returns the durable upload receipt only after the Host upload service succeeds.

Downloads: a successful `file.read` call result's `value` is exactly `DownloadMetadata {transferId,name,mediaType,bytes,offset,eof}`, validated with `validateDownloadMetadata`. The result envelope's id remains the call correlation id. There is no additional download.open. Controller grants `download.credit {id:transferId,fence,chunks}`. Host sends credited chunks and `download.end {id:transferId,fence,chunks,error?}`. Successful end requires exact declared bytes and contiguous chunk count. An error end aborts the transfer and drops buffered bytes. Generic watch end is never interpreted as download completion. A download range is at most 1 MiB; the downloader serially requests ranges and enforces the 32 MiB total/Host ceiling.

Credit grants are positive integer chunks, at most four per frame. They acknowledge consumed receiver capacity; callers must not replenish credit merely because bytes arrived on the socket. The total of unused receiver credit and its queued chunks never exceeds four. `TransferWindow` accounts sender credit, sequential indices and exact final bytes. `TransferReceiver` enforces transfer/control IDs, sequential indices, declared bytes, queue byte ceiling and credit. It copies only validated payload bytes so a tiny view cannot retain a giant backing buffer. Empty binary chunks are invalid; a zero-byte transfer has zero chunks and completes with end(0). Transfer accounting faults terminate the transfer and release its credits/owned buffers.

### Binary layout

The fixed 44-byte header uses network byte order. Frames contain exactly the header and declared payload.

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 4 | Magic ASCII WCB1 (version 1) |
| 4 | 16 | transferId UUID bytes |
| 20 | 16 | controlId UUID bytes |
| 36 | 4 | uint32 chunk index, starting at 0 |
| 40 | 4 | uint32 payloadLength |
| 44 | payloadLength | payload |

`encodeChunk(id,controlId,index,data)` enforces the default 64 KiB ceiling. `decodeChunk(data,limits)` checks the total frame length before parsing the fixed header, then magic, declared length and exact payload size before returning a payload view. A lower Host chunk ceiling is enforced by receiver/sender accounting. Binary frames omit instance/runtime/auth; those come from the authenticated current Fence. Decoders do not silently ignore an unknown version.

## Defaults and queue ownership

| Resource | Default |
| --- | --- |
| JSON frame | 256 KiB in UTF-8 |
| Opted native read result/event | 1.75 MiB in UTF-8, at most 256 fragments |
| Binary payload | 64 KiB |
| File | 32 MiB |
| Concurrent calls / watches / uploads | 16 / 16 / 2 |
| Per-instance queued plus WebSocket buffered bytes | 4 MiB |
| Unconfirmed chunks per transfer | 4 |
| Call timeout | 30 seconds |
| Transfer without byte progress | 60 seconds |
| Heartbeat interval / disconnect release | 10 / 30 seconds |

`validateLimits` rejects zero, negative, fractional, unsafe, NaN and infinite values. Chunk bytes must fit uint32; timer values fit the runtime's positive signed-32-bit timeout. `effectiveLimits` takes the smaller configured/Host values. `validateHeartbeat` requires the loss deadline to exceed the interval. Defaults require pressure-test evidence and documentation changes before adjustment.

`BoundedQueue(limit,controlReserve)` retains copied nonempty byte frames. Data bytes alone cannot exceed limit minus reserve; combined control/data bytes cannot exceed limit. Control overtakes data while preserving FIFO within each priority. `enqueue(priority,data,bufferedBytes=0)` also charges the current WebSocket bufferedAmount against the total bound, so socket buffering cannot become a hidden extra queue. Empty items are rejected to keep object count bounded by byte capacity. `take()` removes one owned frame; `clear()` releases all frames. Zero queue capacity is allowed and accepts no frames. Every instance shares one aggregate queue/budget; creating independent full-capacity queues per transfer does not enforce the instance bound.

### Native large read compatibility

The optional `large-json-v1` Host capability permits `fragments:true` on watches and only these read calls: `ui.catalog`, `ui.search`, `session.list`, `session.page`, `file.changes`, `file.diff`. Requests, writes, interactions and uploads retain their existing limits. A browser must reload to load the new transport; an old browser keeps its old limits. This extension does not change DSH business data, UI components or public API semantics.

Host `json.fragment` frames identify the original result/event, operation ID, full fence, zero-based index, total parts and total UTF-8 bytes. Every physical frame remains at most 256 KiB. Host validates and serializes in bounded pieces, serializes large sends through one window, and accounts native payload ownership in the same 4 MiB aggregate budget. Browser reserves twice the declared body size before retaining any fragment, checks ordering and byte counts, then validates the reconstructed original envelope and fence again. Relay only tracks metadata and forwards bounded frames. Neither side accepts nested fragments or opt-in on mutations.

The 1.75 MiB logical ceiling leaves room for assembly and frames within the default aggregate budget; concurrent overload still fails closed with `RESYNC_REQUIRED`. It is not unlimited profile/history support. Incomplete transfers have an absolute deadline. Cancellation discards retained data but drains ordered metadata; Relay returns a terminal `TRANSFER_CLOSED` acknowledgment for opted operations, including cancellation before Host dispatch or after Host completion. Cancellation never stops accepted native Agent work. Existing non-opted clients retain the original cancellation behavior.

Socket adapters must configure inbound transport maxPayload before WebSocket allocation: no larger than max(jsonBytes, 44 + chunkBytes), then apply the more specific parser bound. They must sample bufferedAmount before enqueue/send, drain only within the combined budget, reserve control capacity and disconnect on failed transport progress. Existing buffered socket bytes cannot be reclaimed by clearing this JavaScript queue. Concurrent call/watch/upload admission limits, sender idle deadlines and call timers are consumer responsibilities using the exported limits.

`TransferReceiver` is an async iterator with at most one pending next(). Its idle timer resets only on valid received chunks, is removed on successful wire end, and is cleared on every abort/dispose/error. Ended queued data remains abortable until drained. Abort rejects pending reads; explicit dispose or iterator return settles pending reads as done. Both release all unconsumed queues/listeners/timers. On Fence replacement, the owner must dispose the receiver even if no subsequent binary frame arrives. No generator waits forever during plugin unload.

## Prompt admission and uncertain retries

Public rc.2 does not guarantee that two prompt admissions with the same business requestId produce one turn. A fresh `session.prompt` omits `reconcileOnly` and uses a newly minted requestId. An uncertain/disconnected retry MUST set `reconcileOnly:true`; false, null, numbers and strings are invalid. The flag is transport metadata and MUST NOT reach a DSH SessionPromptRequest. Reconciliation joins an existing in-flight attempt or proves prior admission from authoritative public durable history/inbox. It may return `{accepted:true}` on proof. Missing or unprovable acceptance returns `RESULT_UNCERTAIN`; it never authorizes another prompt invocation. Users check the outcome before deciding on a separate fresh submission.

Host adapters bound unresolved admission gates (16 per Host in the current adapter) without evicting unresolved attempts. They recheck each caller's Fence and live scope after joining/lookup awaits. Current adapter lookup uses a 64-message opening follow cut and at most 64 older 64-message pages at that exact throughSeq. Read failures, nonprogressing pages, missing baselines and capped incomplete scans remain uncertain. Durable user/message and agent/inbox/spliced inserted source.rpcId records can prove admission after adapter recreation; absence cannot prove an uncertain attempt was never submitted. There is no v1 persistent admission-intent journal. Transport cancellation preserves known successful admission receipts while current authority remains valid and never cancels the Agent loop.

## Host file consumer ownership (Task 9)

`UploadManager(ctx,hostFence,scope,transport,limits?)` exports the specified `open`, `chunk`, `end`, `cancel`, `dispose` plus `scopeChanged()`. `UploadTransport` requires `credit(id,copiedFence,chunks)`, `reserve(bytes):release`, and `failed(id,copiedFence,ProtocolError)`. The owner must bind reserve to the **one instance aggregate** budget including both socket directions and every other queued buffer; per-transfer full budgets are insufficient. Reservations cover each owned chunk plus its44-byte frame overhead and release after Host consumption or synchronous cancellation. Credit replenishes after consumption, not arrival. Native outstanding calls still count against upload admission after cancel until their actual promises settle.

There is exactly one upload terminal owner. `end()` owns its returned durable receipt or rejection (including receipt timeout); a failed `chunk`/`open` and explicit same-Fence cancel belong to their transport caller. Autonomous idle/native failures with no end caller invoke `failed` once after cleanup, so Task10 can send the typed upload `result` error even without `upload.end`. Generation invalidation/dispose suppresses autonomous stale terminals. Throwing/rejecting notification queues cannot prevent cleanup or create unhandled rejections. The caller must not return a second terminal for an already autonomously failed transfer. Task10 must keep its operation identity ledger and route late frames by that ledger; UploadManager does not implement recent-ID reuse policy. Physical credit/failure/result sends must check current Fence again. Workspace registry notifications call `scopeChanged` synchronously; HostFence replacement/disconnect aborts registered upload lifetimes immediately. No operation cancels an accepted Agent turn or deletes arbitrary file bytes. Public staged receipt lifecycle remains Host-owned, including post-cancel uncertainty.

Bind `FileService(ctx,scope,admission)` per dispatch using the required AdditionalHandlers admission callback (and its caller signal where applicable). Scope requires the same selected current registry as other adapters and public `fs`/`typert`/`sessions` context for recorded files. A whole summary read uses `scope.bindRecordedWorkspace(sessionId,recordedRoot,signal?)` to retain its initial selected workspace and canonical Host root; its returned `RecordedWorkspaceAuthority` provides `assertCurrent():Promise<void>` for canonical-root checks and `assertCurrentSync():void` for a synchronous live-authority check after the caller’s final await. It binds public live Session identity, header identity/cwd, and selected workspace. `assertCurrentSync` must run immediately before invoking or returning recorded data. Public rc.2 records only live Sessions with cwd; missing live Session/cwd fails closed. Every awaited lookup/resolver is followed by that same live witness, and lookup root must equal the authoritative header cwd. This supports certified stock live-header-first lookup semantics, not a custom conflicting workspaceFileScope resolver. `RecordedWorkspaceChanged` keeps wire code OUT_OF_SCOPE but invalidates the entire accumulated result instead of filtering one path. The original recorded-file FileService handles `readChanges`/`readDiff`. The current `current-files-v1` adapter additionally binds supported local-provider reads to session/workspace authority, contained file handles and a version token. Unsupported providers retain `PROTOCOL_UNSUPPORTED`. Download metadata/credit/end framing is unchanged.

Upload admission counters belong to one **Host-lifetime UploadManager**. Reuse that manager across Fence invalidation/install: per-entry generation listeners cancel old transfers synchronously, while unresolved native calls retain their permits until settlement. `dispose()` permanently closes the manager and is for plugin unload, not each reconnect. Recreating managers on every generation would reset that local counter and defeat the cross-generation bound; any consumer that replaces managers must instead retain equivalent Host-wide active-upload permits. Task10/13 must verify this ownership alongside the shared socket budget; the Task9 per-manager tests alone do not certify the future integrated Host transport.

## Browser synchronization and authorization discovery (Task 11)

Native browser WebSocket APIs hide HTTP Upgrade rejection bodies. The fixed `POST /v1/instances/:id/control-status` route accepts exactly `{}`, requires the canonical Origin and instance cookie, and uses the existing authorization rate/body/deadline limits and no-store/no-CORS headers. It performs no cookie renewal, lease acquisition or mutation. Success contains only `{hostOnline:boolean,remoteConnected:boolean}`; authentication failures retain the ordinary typed codes. These values are advisory: the subsequent authenticated Upgrade and exact Host ACK remain authoritative. Browser preflight and bounded reconnect/backoff repeat this probe after unknown Upgrade failures; they never invent an expiry or revocation cause from close1006. A busy page needs the existing controller to disconnect/expire before a new connection can succeed.

Interaction watch values now include `{kind:'interactions-ready'}` after the authenticated native `$events` ready frame. Published rc.2 registers its client and queues existing deliveries before that ready frame; this proves observer attachment, not that there are no pending deliveries. The signal contains no native client identity. Ordered live requests are `{kind:'interaction',sessionId,deliveryId,event,request}`; `sessionId` is the already scoped native Agent identity. `interaction-cancel` still names the Host-issued deliveryId. Browser retains one global pending map per Fence, filters it for the selected session, and never recreates an actionable delivery from a historical projection.

The browser transport's internal `registerSynchronizer`/`holdSync` contract binds all callbacks to socket/Fence plus selection revision. Wire ready enters syncing. A `SessionStore` registered before connect owns one workspace, one control, and one interaction watch per Fence; only the selected session follow changes on navigation. Matching workspace/control baselines, interaction attachment, current follow snapshot and stop-token publication release ready. Without a synchronizer the transport remains read-only. Reads/watches can run while syncing; prompt/stop/answer/create/upload cannot. Missing baselines time out; old callbacks and old Fences cannot release a replacement barrier. Reconnect cancels observers/transfers, retains no actionable old deliveries, and never cancels accepted Agent work or replays actions.

`createDshRemote` is the approved public follow/page/control fallback facade, not a replacement DSH Client and not a fabricated RemoteResult envelope. The unavailable rc.2 standalone client classes are not imported. The pinned public `@deepseek-ai/dsh-llm/assistant-stream` pure codec expands compact assistant opening baselines into timed live chunks; the browser bundle contains no Host/core service runtime. Durable records remain ordered by seq, pages stay bound to their follow cut, gaps reopen follow, and durable turn/step or end.outcome.seq settlement supersedes transient state. `SubmissionQueue.retry` only checks an uncertain result with the original business requestId/content and `reconcileOnly:true`. UI copy must describe checking the outcome, never promise a resend. DraftStore's `capture`/`clearAccepted` and queue `submitDraft` clear only the accepted draft revision; storage failure falls back to memory and exposes `persistenceWarning`.

The native browser composition now connects stock document previews and browser downloads to the negotiated contained-read adapter. Unit protocol fixtures are supplemented by native preview/download browser tests; see release notes for executed validation.

The same SessionStore subscriptions expose `getWorkspaceSnapshot():Json|null` and `getControlSnapshot():Json|null`. They return detached public baseline values and apply validated workspace upsert/remove/order/archive/pin or per-session/per-key projection deltas; equal/stale key revisions do not overwrite newer data. Values are initially null, retain their last read-only cache while offline, and reset to null when a new wire-ready Fence begins syncing. Consumers pair them with the connection phase. References stay stable until that cache changes. Session selection keeps these global observers/caches; generation replacement discards old callbacks. No extra UI observer or endpoint is needed.

Task12 must route live approval/question answers through `SessionStore.answer(deliveryId,answer,signal?)`. This issues one existing interaction.answer call and removes the captured global delivery only after authoritative accepted:true under the same synchronization generation and exact pending-entry identity. Switching the selected session does not prevent settlement. Missing/settled deliveries fail STALE_ACTION before dispatch; validation errors, rejected/unproven results and uncertainty retain the delivery and never trigger replay. Caller UI must show uncertainty honestly. Late native cancellation is harmless; no new Host wire event or native capability is implied.

Non-OK login/status HTTP responses only establish authorization failure when they contain an explicit known authorization code. Missing, malformed, non-JSON or unrecognized error envelopes are sanitized availability failures and follow bounded connection backoff/reprobe, not an invented AUTH_REQUIRED/AUTH_EXPIRED cause. Raw login fetch failures use the same availability classification.
