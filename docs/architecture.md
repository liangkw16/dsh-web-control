# 架构与适配原则

三个运行部分：DSH 插件 Host、可信的自托管 Relay、浏览器。Host 主动建立 WSS；浏览器通过控制链接认证后认领一个控制租约。Relay 转发有限命令和流式事件，不远程操纵桌面鼠标键盘。

## 最大化复用原版 Web

固定公开 DSH rc.2 浏览器资源，保留原版业务 JS/CSS 字节。远端启动层组合原版服务与插件；桥接会话、工作区、问题/审批、队列、上传、历史 diff 和有限文件服务。新增下载按钮通过公开操作槽注入。

接收到状态快照后订阅变化与进度，使用运行实例、序列和控制租约处理重连与过期响应。新页面替换旧页面后，旧控制请求失去权限。不会从 URL 接受任意 RPC 名称或本地文件路径作为全局读取入口。

## 文件

每次读取验证会话仍属于已注册工作区，文件提供方与实时会话作用域一致。macOS/Linux 本地提供方使用只读受限句柄；路径身份、文件版本在读取前后复验。符号链接、越界路径、非常规文件和不支持的提供方均拒绝。版本变化不能拼接成一次成功下载。

原版 Markdown 没有图片 URL 注入点，有限 Service Worker 仅拦截所属原版文档的同源图片读取，将请求转回当前控制文档的有限文件命令。没有通用 Relay 文件 HTTP 路由，不持久缓存正文。

## 安全与升级

TLS 在 Relay 终止，Relay 是信任边界，不能声称端到端加密。设备注册与浏览器控制使用不同凭据。凭据存入 DSH profile credential provider，不能嵌入插件设置、源码或镜像。

上游升级必须更新版本矩阵、资源来源与哈希，运行原版 UI 差异/能力检查和浏览器回归。未知 DSH 版本 fail closed；不能靠 CSS 隐藏按钮代替 Host 权限校验，也不能用新的聊天页面替换原版交互。

工作目录：`packages/plugin`、`packages/relay`、`packages/web`、`packages/protocol`。协议细节见 [protocol.md](protocol.md)。
